# 🎵 Jam Queue Manager

Spotifyで友人と一緒に音楽を流すとき、**みんなの曲リクエストを公平に交通整理して、自動でホストの再生キューに流し込む**Webアプリです。

Spotify公式のJamは「次に再生」を全員が触れる反面、同じ人の曲が連続したり、順番の管理ができません。このアプリはJamの代わりに(または併用して)、リクエストの受付と順番決めを引き受けます。

## できること

- 📱 **友人はスマホのブラウザからアクセスするだけ**(アプリインストール不要)
- 🔍 曲の探し方は3通り: **検索** / 自分の**お気に入り(Liked Songs)** / **自分のプレイリスト**
  - お気に入り・プレイリストを使う場合のみ、ゲスト自身のSpotify連携が必要(検索だけなら不要)
- 🚦 **同じ人の曲が連続しないように自動で並べ替え**(ラウンドロビン)
  - ただしリクエストしているのが1人だけの場合は連続もOK
- ↕️ **自分がリクエストした曲は、自分の中での順番を入れ替え可能**(他人への割り込みは不可)
- 📀 **誰もリクエストしていない時は、設定したプレイリストの曲を順番に再生**
- 🔄 曲の終わり際に次の1曲を自動でSpotifyのキューへ投入。**再生操作は一切不要**
- ⏭ **手動スキップにも対応**: Spotifyアプリ側で「次へ」を押されても、正しい順番の曲へ自動で繋ぎ直す
- 👀 「今なにが再生中か」「次に何が流れるか」「誰のリクエストか」が全員の画面にリアルタイム表示

## 仕組み

```
友人のスマホ ──(Wi-Fi)──> このサーバー(PC等で起動) ──(Spotify Web API)──> ホストのSpotify再生
   検索・リクエスト          順番の交通整理                  曲の終わり際にキューへ1曲投入
```

- ホストがSpotifyにログインします(**Premium必須**。キュー操作APIがPremium限定のため)
- サーバーはホストの再生状態を数秒おきに監視し、曲の残りが約20秒になったタイミングで「次に流すべき1曲」を決めてSpotifyのキューに追加します
- 1曲ずつ直前に投入する方式なので、後から他の人がリクエストしても正しく割り込めます

### 手動スキップされた場合の挙動

- **次の曲が投入済み(残り20秒以内)の場合**: Spotifyはキュー先頭=投入済みの曲を再生するので、そのまま正しく流れます
- **投入前にスキップされた場合**: 一瞬だけ別の曲が流れますが、サーバーが数秒以内に検知し、正しい次の曲を投入して自動でスキップし直します
- リクエストが1件も無いときにホストが手動で曲を選んだ場合は、その選曲を尊重します(曲の終わりから再び自動運転に戻ります)
- アプリ内の「⏭ スキップ」ボタンを使えば、最初から正しい曲に一発で繋がります

## セットアップ

### 1. Spotify Developerアプリの作成(初回のみ)

1. https://developer.spotify.com/dashboard を開き、ホストのSpotifyアカウントでログイン
2. **Create app** で適当な名前のアプリを作成
3. **Redirect URIs** に `http://127.0.0.1:8888/callback` を追加して保存
   - ※ Spotifyの仕様で `localhost` は使えません。必ず `127.0.0.1` で
   - ゲストのSpotify連携も使う場合は、後述のHTTPS URLも追加登録
4. **Client ID** と **Client Secret** を控える

### 2. サーバーの起動

Node.js 18以上が必要です。

```bash
npm install
cp .env.example .env
# .env を編集して SPOTIFY_CLIENT_ID / SPOTIFY_CLIENT_SECRET を設定
npm start
```

### 3. ホストのログインと初期設定

1. サーバーを動かしているPCのブラウザで http://127.0.0.1:8888 を開く
2. 「⚙️ ホスト設定」→「Spotifyでログイン」で認可する(トークンは `data/` に保存され、次回以降は不要)
3. 同じく「ホスト設定」で、誰もリクエストしていない時に流す**プレイリストのURL**を貼って設定
4. ホストのSpotifyアプリ(スマホでもPCでも可)で、何か1曲再生を始める
   - 以降はこのアプリが自動でキューを繋いでいきます

### 4. 友人を招待

- 友人はホストと同じWi-Fiに繋ぎ、スマホのブラウザで `http://<サーバーPCのLAN IP>:8888` を開くだけ
  - LAN IPは `ipconfig`(Windows) / `ip addr`(Linux) / `ifconfig`(Mac) で確認
- 初回に名前を入力してもらえば、検索タブから「＋」を押すだけでリクエスト完了

### 5. ゲストが「お気に入り」「マイプレイリスト」から選べるようにする(任意)

ゲストが自分のSpotifyアカウントを連携する場合、2つ準備が必要です:

1. **HTTPSでのアクセス経路**
   SpotifyのOAuthは `127.0.0.1` 以外では **HTTPSのRedirect URIしか許可されません**。LANの `http://192.168.x.x` からは連携できないため、[Tailscale Funnel](https://tailscale.com/kb/1223/funnel) や [cloudflared tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) 等でサーバーをHTTPS公開し、そのURL(例 `https://xxxx.trycloudflare.com`)を全員に共有してください。
   Dashboardの **Redirect URIs** に `https://<そのドメイン>/callback` を追加登録します(Redirect URIはアクセス元URLから自動で決まるので、.envの変更は不要)。
2. **Development modeのユーザー登録**
   Spotifyアプリが審査前(Development mode)の間は、DashboardのUser Managementに**連携するゲストのSpotifyアカウントのメールアドレスを登録**しておく必要があります(最大25人)。

連携しないゲストも、検索タブからのリクエストは普通に使えます。

> **補足**: Spotifyアプリの「ダウンロード済み」は端末内の情報でWeb APIからは取得できないため、お気に入り(Liked Songs)とプレイリストで代替しています。よく聴く曲は大抵どちらかに入っているはずです。

## 順番決めのルール

1. リクエストがある場合:
   - 各ユーザーの「一番先頭のリクエスト」が候補になる(自分の中の順番は↑↓で変更可能)
   - 最後に自分の曲が流れてから一番時間が経っている人を優先(ラウンドロビン)
   - **直前に流れた人と同じ人は、他にリクエストしている人がいる限り選ばれない**
   - リクエストしているのが1人だけなら連続で流れる
2. リクエストが無い場合: 設定したプレイリストを頭から順にループ再生
3. プレイリストの曲が流れた後は「直前の人」の縛りがリセットされる

## 制限・注意点

- **Spotify公式のJam機能そのものをAPIで操作することはできません**(Jamのキューの並び替え・削除のAPIは非公開)。このアプリは「ホストの再生キューに1曲ずつ投入する」ことで同等の体験を実現しています
- **一度Spotifyのキューに投入した曲(「投入済み」表示)の取り消し・並べ替えはできません**(投入は曲の残り20秒からの1曲だけなので影響は最小限です)
- 友人がSpotifyアプリのJam/キューから直接曲を追加すると、このアプリからは見えないため交通整理の対象外になります。**曲の追加はこのWebアプリ経由に統一**してください
- ホストはSpotify **Premium** が必要です(ゲストは連携する場合でもFreeでOK)
- みんなで同じ音を聴く方法は自由です: スピーカーで流す、公式Jamに参加して各自のデバイスで聴く、など(Jam併用の場合も曲の追加はこのアプリから)
- このアプリ自体に認証は無いので、トンネル等でインターネット公開する場合はURLを知っている人だけに共有してください

## 主なファイル

| ファイル | 役割 |
|---|---|
| `server.js` | Expressサーバー。OAuth(ホスト/ゲスト)、再生監視ループ、手動スキップ補正、交通整理ロジック、SSE配信 |
| `public/index.html` `app.js` `style.css` | スマホ向けWeb UI(検索/お気に入り/プレイリスト、リクエスト並べ替え、再生状況のライブ表示) |
| `.env.example` | 環境変数のテンプレート |
| `data/` | トークン(ホスト・ゲスト)とプレイリスト設定の保存先(git管理外) |
